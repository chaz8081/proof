## Post-v1.0 Ideas (Not Yet Filed)
These came up during development but were deferred as out-of-scope for v1.0. They're worth considering for v1.1 once the tool has been used in anger for a week or two:

1. **Ollama integration** — local model support via the Reviewer interface. Design supports it, just needs a second implementation.
2. **Prompt tuning** — the system prompt works but could be refined based on real review quality feedback. Consider A/B testing different prompts.
3. **PR comment context** — currently the AI only sees the diff. Including PR comments/discussion could improve review quality.
4. **Notification hooks** — Slack/webhook notification when a draft review is ready for curation.
5. **Multi-account support** — `proof` currently uses one GITHUB_TOKEN. For users with multiple GitHub accounts (like chaz8080/chaz8081), per-repo token config would help.

These should be driven by real usage feedback, not speculative planning.
